# スパイ7分の1 - セットアップ手順(Phase 1・GitHub Pages版)

## 今回実装した範囲
- ホーム画面(ルーム作成 / 参加)
- ロビー(参加者のリアルタイム同期、3〜7人でホストが開始可能)
- 役職の秘密決定(スパイ75% / 平和村25%)と、本人だけへの役職公開

## 未実装(次のステップ)
- 4つのミニゲーム(伝達・判断一致)
- 作戦会議 / 投票 / 勝敗判定
- 誰かが切断した場合のルーム解散処理

構成: **静的ファイル(HTML/CSS/JS)はGitHub Pagesでホスティング／データはFirestoreを利用**します。
Firestoreはどこにホストされたページからでも呼び出せるので、この組み合わせで問題なく動きます。

---

## セットアップ手順

### 1. Firebaseコンソールでの設定
1. 既存のFirebaseプロジェクトを開く
2. 「構築」→「Authentication」→「Sign-in method」で **匿名（Anonymous）** を有効化
   - ユーザーには一切ログインUIを見せません。裏側で自動的に匿名認証しています
3. 「構築」→「Firestore Database」でデータベースを作成(まだなければ)
4. `firestore.rules` の内容をFirestoreの「ルール」タブに貼り付けて公開
   - またはFirebase CLIがあれば `firebase deploy --only firestore:rules`
5. 「プロジェクトの設定」→「マイアプリ」でWebアプリを追加(まだなければ)し、表示された設定値を `firebase-config.js` に貼り付ける
6. **重要:** 「Authentication」→「Settings」→「承認済みドメイン」に、GitHub PagesのドメインID `<GitHubユーザー名>.github.io` を追加する
   - これを忘れると匿名認証がブロックされ、アプリが動きません

### 2. GitHubリポジトリの準備
このプロジェクトフォルダはすでにgitリポジトリとして初期化済みです(`git log` で確認できます)。

```bash
cd spy-game
git remote add origin https://github.com/<あなたのユーザー名>/<リポジトリ名>.git
git push -u origin main
```

### 3. GitHub Pagesを有効化
1. GitHub上でリポジトリの `Settings` → `Pages` を開く
2. 「Source」を `Deploy from a branch` にし、ブランチ `main` / フォルダ `/ (root)` を選択して保存
3. 数分後、`https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます
4. このURLを手順1-6の承認済みドメインに追加した内容と一致しているか確認してください

### 4. テスト方法
- ブラウザを3つ以上開く(またはスマホ+PCなど別端末)
- 1つ目で「ルームを作る」→ルームIDが表示される
- 残りで「ルームに参加する」→同じルームIDを入力
- 3人以上揃うとホスト画面に「ゲーム開始」ボタンが有効化
- 開始すると、各端末に自分だけの役職(プレイヤー/スパイ)が表示される
  - 他の端末の画面を覗いても、自分以外の役職は見えないことを確認してください(Firestoreルールで保護)

## 既知の制限事項
- 役職決定はホストの端末が計算して書き込む方式です(仕様上「サーバーが管理する」のが理想ですが、MVPでは簡略化しています)。友人内の信頼を前提にしています。
- 通信切断時の処理(ルーム解散など)は未実装です。
- リポジトリを **Private** にする場合、GitHub Pagesの利用には有料プラン(Pro等)が必要です。無料で公開する場合はPublicリポジトリにしてください(コード自体に秘密情報は含まれませんが、Firebaseの `apiKey` 等は公開されます。これはFirebaseの仕様上問題ありません。実際のアクセス制御はFirestoreのセキュリティルール側で行います)。
